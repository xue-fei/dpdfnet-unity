## DPDFNet → Unity 16kHz 实时降噪移植

- 参考原始工程 `DPDFNet/`(Python/onnxruntime) 在 Unity 实现流式语音降噪。
- ONNX 模型(baseline/dpdfnet2/4/8, 均为 16kHz, `n_fft=320, hop=160, freq_bins=161, Vorbis窗`)已在 `Assets/StreamingAssets/dpdfnet/`。
- **关键坑**: onnxsim 剥离了 ONNX 自定义 metadata,无法在 Unity 端读 `state` 初值。改用旁路 JSON(`<model>.json`),由 `DPDFNet/generate_unity_sidecar_meta.py` 基于参考工程**确定性**重建初始 state(仅 ErbNorm[32]/SpecNorm[96] 两切片非零,其余为0),并交叉验证 `state_size` 与 ONNX 输入形状完全吻合(38256/45424/52592/66928)。
- C# 实现位于 `Assets/Scripts/DPDFNet/`:`DpdfNetModelConfig`(JSON解析+初值重建)、`VorbisWindow`、`StreamingStft`/`StreamingIstft`(Math.NET FFT 对齐 numpy 约定)、`IOnnxSession`/`OnnxRuntimeSession`(Microsoft.ML.OnnxRuntime)、`DpdfNetProcessor`(核心编排)、`AudioResampler`(Lanczos)、`DpdfNetMicrophoneDemo`(`OnAudioFilterRead` 实时管线 + 块级 AGC)。
- 依赖需手动加 DLL:`Microsoft.ML.OnnxRuntime`(CPU,原生库按平台放 Plugins)、`MathNet.Numerics`。
- 变体映射确认:`baseline=0 / dpdfnet2/4/8 = dprnn_num_blocks=2/4/8`(注释 `# 0 for Baseline | N for DPDFNet-N`)。
- 未做: 离线 WAV 处理封装、生产级时钟重采样(当前 resample 路径为简单实现,可能有轻微时序漂移)。
- **编译/运行时修复**: `OnnxRuntimeSession.cs` 针对定制版 `onnxruntime@f8cfbf149d`(无 ToArray/Buffer 扩展)：`NodeMetadata.Dimensions` 是 `int[]`(用 `.Length`);`Tensor<float>` 基类无 `ToArray()`、`Buffer` 仅在 `DenseTensor<float>` 上有(public `Memory<T> Buffer`);`params int[]` 索引器对多维张量(spec `[1,1,161,2]`)单下标访问会越界。最终方案: 转型 `DenseTensor<float>` 用 `Buffer.Span` 整块拷贝,非 DenseTensor 兜底用基类公开 `GetValue(int)` 扁平访问器遍历。
- **运行时"听不到声"根因与修复**: `OnAudioFilterRead` 的 `data` 处于 Unity 输出率(`AudioSettings.outputSampleRate`,通常 48k),而 `needsResample` 原先用 `micClip.frequency`(请求到的麦克风率,常为 16k)判断→误判不需重采样,把 48k 音频当 16k 直喂模型,深度降噪网把分布外输入当噪声抑制→静音。改为基于 `dspRate=AudioSettings.outputSampleRate` 决策;重采样后每帧输出≈1026≥块长1024,队列不枯竭且无缺口。对照 `real_time_demo.py` 确认 C# STFT/ISTFT 数学完全正确(rfft/irfft 缩放、Hermitian、OLA、初值切片一致)。Demo 新增 `monitorBypass`(直出原始麦克风,隔离采集vs处理)与 RMS/帧耗时诊断日志。
- **用户已确认**: 应用上述 `dspRate` 修复后重新编译运行,可正常听到增强后的讲话声(此前诊断日志 outRMS≈0 是修复前/过渡态)。✅
- **残留观察(非阻塞)**: 该 demo 采用"无状态逐块 Lanczos 重采样 + 入/出队列"架构,日志显示 `qOut` 随运行缓慢增长(1440→5024,~2-4 样本/块),源于 `ceil()` 取整与帧余数累积,长期运行会产生轻微延迟爬升(latency creep);且逐块重采样在块边界有相位重设,理论上引入轻微边界伪影。当前 demo 可正常工作,如后续发现延迟漂移或音质边界杂音,可改为有状态(stateful)重采样并按精确 480(48k)→160(16k)→480(48k) 整数倍帧对齐来彻底消除。
